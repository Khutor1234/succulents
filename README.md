# 🌵 Succulents — інтернет-магазин сукулентів

React + Firebase. Архітектура описана в [docs/system-design.md](docs/system-design.md).

```
web/         сайт (Vite, React, TypeScript, Tailwind, Zustand, TanStack Query, i18next)
functions/   бекенд — Cloud Functions на Node (оформлення замовлення, Telegram)
firestore.rules, storage.rules   хто що може читати й писати
```

## Що потрібно встановити один раз

- Node.js 22+ (LTS), Git, Java 21 (для емуляторів Firebase)
- Firebase CLI: `npm install -g firebase-tools`
- Залежності проєкту: `npm run setup`

## Локальний запуск

Справжній Firebase-проєкт для розробки **не потрібен**: усе працює на локальних емуляторах (проєкт `demo-succulents`).

1. **Термінал 1** — емулятори (база, вхід, функції):
   ```
   npm run emulators
   ```
   Панель емуляторів: http://127.0.0.1:4000 — там видно товари, замовлення, користувачів.
2. **Термінал 2** — тестові товари (дані емулятора не зберігаються між запусками, тому після кожного старту):
   ```
   npm run seed
   ```
3. **Термінал 2** — сайт:
   ```
   npm run dev
   ```
   Відкрити http://localhost:5173

### З телефона
Телефон і комп'ютер мають бути в одній Wi-Fi мережі. Дізнатися адресу комп'ютера: `ipconfig` → «IPv4 Address» (напр. `192.168.0.218`).
На телефоні відкрити `http://<ця-адреса>:5173`. Якщо не відкривається — Windows Firewall має дозволяти Node.js і Java (вікно з запитом з'являється при першому запуску).

### Адмінка (локально)
`npm run seed` створює тестового продавця — логін і пароль виводяться в терміналі (і записані в `functions/scripts/seed.mjs`).
Увійти на сайті → «Адмінка» (http://localhost:5173/admin): товари з фото, приховування, замовлення й зміна статусу.
Якщо скасувати замовлення, товари автоматично повертаються на склад.

### Хто продавець
Список продавців — email-и через кому в змінній `SELLER_EMAILS`:
- локально — `functions/.env.local`;
- на справжньому сайті — `functions/.env` (деплоїться разом із функціями).

Після входу сайт сам звіряє роль: акаунт зі списку отримує «Адмінку», а той, кого зі списку прибрали, втрачає її при наступному вході.
Рахується тільки підтверджений email (Google-акаунти підтверджені завжди).

## Telegram-сповіщення про замовлення

1. У Telegram написати [@BotFather](https://t.me/BotFather) → `/newbot` → отримати **токен**.
2. Написати своєму боту будь-яке повідомлення (або додати його в групу продавців).
3. Відкрити `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — у відповіді знайти `"chat":{"id": ...}`. Це **chat id**.
4. Локально: скопіювати `functions/.secret.local.example` → `functions/.secret.local` і вписати обидва значення.
5. На проді: `firebase functions:secrets:set TELEGRAM_BOT_TOKEN` і `firebase functions:secrets:set TELEGRAM_CHAT_ID`.

Поки токена немає, функція просто пише текст повідомлення в лог емулятора.

## Мова

Сайт українською. Усі тексти інтерфейсу — у `web/src/i18n/uk.ts`.

## Вхід через Google

Локально емулятор показує тестове вікно вибору акаунта (не справжній Google).
Справжнє вікно Google з вашими акаунтами з'явиться на реальному Firebase-проєкті: Authentication → Sign-in method → увімкнути Google, а домен сайту додати в Authorized domains.

## Логи й помилки

Сервер пише структуровані журнали в Cloud Logging, сайт і сервер шлють помилки в Sentry.
Як шукати за покупцем чи замовленням і як підключити Sentry — [docs/monitoring.md](docs/monitoring.md).
