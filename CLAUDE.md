# Магазин «сукуленти.» — пам'ятка для Claude

Інтернет-магазин сукулентів власниці Олександри. Живий сайт: https://succulents-shop-ua.web.app
(Firebase-проєкт `succulents-shop-ua`, репозиторій `Khutor1234/succulents`). Увесь код пише Claude.

## Як працювати з власницею

- Відповідати **українською**, простими словами, без технічного жаргону. Вона не програмістка.
- Налаштування, команди й перевірки робити самому; від неї — лише те, що вимагає її акаунта (вхід, оплата, паролі).
- **Не комітити й не пушити, поки вона не скаже «Публікуй».** Push у `main` одразу публікує сайт (див. нижче).
  Спершу показувати зміни на localhost.
- Паролі, ключі, платіжні дані не вводити й не читати (`.env` з секретами, токени firebase-tools тощо).
- Справжню базу на проді змінювати лише через адмінку сайту (напр. сторінку «Імпорт»), а не скриптами з токенами.

## Стек і структура

```
web/        сайт: Vite + React 19 + TypeScript, Tailwind v4, react-router, TanStack Query, Zustand, i18next
functions/  Cloud Functions (Node 22): createOrder, бонуси, статуси замовлень, Telegram, syncAccount (роль продавця)
docs/       system-design.md (архітектура, модель даних), deploy.md, monitoring.md
firestore.rules, storage.rules, firestore.indexes.json
```

- Усі тексти інтерфейсу — `web/src/i18n/uk.ts` (лише українська).
- Каталог: `web/src/features/catalog` (картки `ProductCard.tsx`, сторінки `pages.tsx`, пошук `SearchPage.tsx`, запити `api.ts`).
- Адмінка: `web/src/features/admin` (вантажиться окремим шматком, маршрути в `AdminApp.tsx`): `/admin` — огляд із плитками,
  `/admin/products/:id` і `/admin/products/new` — форма товару, `/admin/orders`, `/admin/categories`, `/admin/customers`,
  `/admin/analytics` (продажі + рослини: роди, форми, «Кольори в назвах» англійською зі списком рослин), `/admin/pedigrees`
  («Родоводи»: трійки, батько й дитина, «Нащадки» — батько і всі його діти, форми однієї рослини — розрахунок у `pedigrees.ts`;
  батько й дитина мають бути **в однаковій формі**, без «варієгатний батько → звичайна дитина»), інструменти `/admin/import`
  і `/admin/forms` («Виправити форми»: variegata/cristata/monstrose → «мутація від» звичайної версії, навіть якщо її немає
  в магазині — тоді на сайті назва без посилання). **Окремого списку товарів немає** — товари керуються в магазині: кнопки
  продавця на картках, «Вибрати» (масові дії, `BulkBar`), «Додати» в каталозі й пошуку.
- Пов'язані рослини під товаром — `catalog/RelatedPlants.tsx`; для рідкісних родів (до 10 рослин на сайті) — ще й «Інші рослини роду».
- Блог: статті прямо в коді — `web/src/features/blog/articles.ts`.
- Назви рослин і теги-форми: `web/src/lib/plants.ts`, `web/src/lib/plantName.ts`.
  Повна назва = рід + сорт + форми з галочок, напр. «Echeveria Lola variegata».
- Ціни зберігаються в **копійках** (`price: 28000` = 280 грн).
- Фото товарів: `products/<id>.webp` (1200 px) + мініатюра `products/thumbs/<id>.webp` (480 px, `web/src/lib/thumbs.ts`).
  Картки й списки показують мініатюру через `SmallImage` (`shared/ui.tsx`), без неї — саме фото. Нові мініатюри робить
  сайт при завантаженні; для старих — плитка «Мініатюри фото» в адмінці (функція `makeThumbs`, sharp).
- Швидкі дії продавця на картці (`useSetStock` тощо в `admin/api.ts`) правлять товар у кеші, а не перечитують сайт.
- Подвійне замовлення: сайт шле `requestId`, `createOrder` пам'ятає його в `orderRequests/{id}` і на повтор віддає те саме замовлення.

## Ролі й видимість

- Продавець (адмін) — `useAuth((s) => s.role === 'seller')`. Список email-ів має збігатися в чотирьох місцях:
  `firestore.rules`, `storage.rules`, `web/.env.production` (`VITE_SELLER_EMAILS`), `functions/.env.succulents-shop-ua`.
- Товар з `isActive: false` прихований: покупці його не бачать (так і в Rules). Продавець бачить приховані **скрізь**
  (каталог, головна, пошук, сторінка товару) з позначкою «Приховано» — запити в `catalog/api.ts` мають параметр `withHidden`.
- **«Готова до продажу»** (`forSale`): `false` — покупці бачать «Немає в наявності» й не можуть замовити, продавець бачить
  справжній залишок. Не вказано = продається (старі товари). Нові товари — приховані й не на продаж.
- **Остання рослина не продається** (`KEEP_LAST = 1` у `web/src/lib/shop.ts` і `functions/src/createOrder.ts`, лише категорія
  «Рослини»): покупцю доступно `stock − 1`. Усе, що бачить покупець, проходить через `forBuyer()` / `buyerStock()` у `catalog/api.ts`;
  сервер (`createOrder`) перевіряє те саме. Продавцю (`withHidden`) — справжні залишки.
- Для продавця в магазині: замість «У кошик» — «Кількість на складі − N +», кнопка «У продажу / Не продається» (для останньої
  рослини — «Не продається» з ⚠-підказкою), Редагувати / око / Копія / Видалити, кругла «скопіювати назву» під сердечком;
  у шапці немає кошика й кабінету, є «Адмінка». Головна для покупця — лише те, що є в наявності.
- Вітальні 100 грн — `functions/src/syncAccount.ts`, лише для підтвердженої пошти (Google — завжди). Продавець бонусів не бачить.

## Імпорт з таблиці (Google Sheet «Рослини»)

`/admin/import`: вставити рядки таблиці (TSV) → попередній перегляд → «Застосувати».
Логіка в `web/src/features/admin/sheetImport.ts`: перейменовує існуючі товари за правилами назв, нові рослини створює
**прихованими** (`isActive: false`, `forSale: false`, залишок 0, ціна = «Max ₴»). Фото й наявність не чіпає.
Кожна зміна (нова назва, нова рослина, оновлення даних) — з галочкою й «Було / Стане»; записується лише вибране.

## Локальна розробка

Емулятори Firebase (проєкт `demo-succulents`), справжній Firebase не потрібен:
```
npm run emulators   # термінал 1
npm run seed        # тестові товари й тестовий продавець (логін — у functions/scripts/seed.mjs)
npm run dev         # http://localhost:5173
```
У Claude desktop: dev-сервер «web» з `.claude/launch.json` (порт 5173). Firebase CLI на Windows — `npx.cmd firebase-tools`.
Перевірка перед публікацією: `npm --prefix web run lint` і `npm --prefix web run build`.

Підводні камені:
- Емулятор функцій на Windows інколи не встигає завантажити їх за 10 с — запускати з `FUNCTIONS_DISCOVERY_TIMEOUT=60`.
- Після кількох правок поспіль dev-сервер інколи тримає стару копію модуля («X is not defined», хоч build проходить) —
  перезапустити «web» (preview_stop / preview_start), а не шукати помилку в коді.
- Скріншоти панелі браузера інколи «з'їжджають» — допомагає resize_window preset desktop.
- Свої тестові дані — лише в емуляторі (`demo-succulents`); скрипт з firebase-admin через `createRequire` із `functions/`.

## Публікація

Push у `main` → GitHub Actions (`.github/workflows/deploy.yml`): lint → build → `firebase deploy` (сайт, функції, правила).
Займає кілька хвилин; стан — `https://api.github.com/repos/Khutor1234/succulents/actions/runs?per_page=1`
(без входу — не більше 60 запитів на годину, тож опитувати раз на 30 с; `gh` на цьому комп'ютері немає).
Коміти — українською, коротко описують зміну для людини.

Після публікації перевіряти: сайт відповідає 200, у бандлі є новий код, функції відповідають як слід
(`curl -X POST .../europe-central2-succulents-shop-ua.cloudfunctions.net/createOrder` → 400, `syncAccount` → 401; **500 — функції лежать**).
Firebase пропускає функції, «які не змінились» (навіть після невдалої спроби) — щоб примусово оновити, потрібна реальна зміна в `functions/src`.

Журнали функцій на проді (лише читання, з дозволу власниці): `npx.cmd firebase-tools functions:log --project succulents-shop-ua -n 100 --debug`
— без `--debug` часто падає «Failed to retrieve log entries»; повторювати кілька разів. 22–24.10.2026 функції не запускались
через збій на боці Google («instance could not start»), минулося саме.
