# Магазин «сукуленти.» — пам'ятка для Claude

Інтернет-магазин сукулентів власниці Олександри. Живий сайт: https://succulents-shop-ua.web.app
(Firebase-проєкт `succulents-shop-ua`, репозиторій `Khutor1234/succulents`). Увесь код пише Claude.

## Як працювати з власницею

- Відповідати **українською**, простими словами, без технічного жаргону. Вона не програмістка.
- Налаштування, команди й перевірки робити самому; від неї — лише те, що вимагає її акаунта (вхід, оплата, паролі).
- **Не комітити й не пушити, поки вона не скаже «Публікуй».** Push у `main` одразу публікує сайт (див. нижче).
  Спершу показувати зміни на localhost.
- Паролі, ключі, платіжні дані не вводити й не читати (`.env` з секретами, токени firebase-tools тощо).
- Справжню базу на проді змінювати лише через адмінку сайту (напр. сторінку «Імпорт»), а не скриптами з токенами.

  і «Перевірка походження» (?tab=origins, `OriginCheckPage.tsx`, `originCheck.ts`: список рослин роду таблицею (колонки: Назва, Правильна назва, Походження, Батько 1/2, Ареал, Селекціонер, Інші назви, Джерело, Примітка, Опис — нинішній опис, перевірка пропонує новий **українською**, для покупців — лише переказ достовірних джерел (llifle, crassulaceae.ch, Huntington ISI, POWO, розплідники тощо), нічого не вигадувати, немає джерела — порожньо; опис — у тій самій картці правки (з малим фото рослини), текст можна відредагувати (правка зберігається в перевірці); у картці дві **окремі** галочки: зліва — загальні зміни (назва, батьки…), «Застосувати опис» — лише опис, можна вибрати одне з двох (FixList: selection / selectable / alsoChosen); у всіх вкладках «Інструментів» і в імпорті біля рослини — мале фото; кнопка «Застосувати» скрізь закріплена (телефон — смуга над нижнім меню, комп'ютер — плаваюча праворуч унизу); рослина знаходиться й за «Іншими назвами», нові інші назви лише додаються) → Claude звіряє назву (лапки, регістр), походження, батьків, селекціонера з worldofsucculents.com та іншими сайтами; рядки про рослини, яких немає в магазині (батьки), — окремо з плюсиком «Створити» (prefill і `breeder`) (сам сайт блокує програми — лише через Chrome власниці) → вставлена таблиця «Зберегти» йде в базу (`originChecks/{slug назви}`: клітинки рядка, лише продавець; повторна перевірка рослини перезаписує стару) →
  з усіх збережених перевірок показано «Було / Стане» з джерелом, записується лише вибране; галочка «Лише неперевірені» копіює тільки рослини без перевірки; кнопка «Скопіювати всі товари» — усі товари (і форми, Hybrid, приховані, не рослини) з головною інформацією таблицею (`fullTsv`) для загальної перевірки бази Claude-ом; корзинка біля правки (і біля рядків «немає в магазині» / «не знайдено») видаляє збережену перевірку — рослина знову «неперевірена»; форми й Hybrid не перевіряються); вкладка «Виправлення» (?tab=fixes, `FixesTab.tsx` + `allFixes.ts`; старі ?tab=forms/names/cultivars ведуть сюди): одна табличка — по рослині всі пропозиції за правилами,
  кожна з поясненням «чому», своєю галочкою й кнопкою «Неактуально» (`fixDismissals/{товар__правило}` з відбитком sig: змінилась пропозиція — з'явиться знову; неактуальна лишається на своєму місці сірою, без галочки, з кнопкою «Зняти «Неактуально»»);
  прийняті зміни однієї рослини зливаються (`mergePatches`, APPLY_ORDER). Правила: форма → «мутація від» звичайної версії (навіть якщо її немає в магазині — назва без посилання),
  культивар → відбір від виду (`formFixes.ts`); селекціонера формам НЕ копіюємо (форму міг вивести інший): правило «Селекціонер форми» пропонує прибрати скопійований, а селекціонер звичайної версії видно в блоці «Від …» («Селекціонер X», `FromRow`), і форма знаходиться за ним у пошуку й фільтрі (`sourceBreeder`, `withSourceBreeders` у lib/search.ts); інші назви звичайної версії → формам (лише відсутні, `planAliasFixes`); рід самої рослини в інших назвах прибирається («Echeveria Lola» → «Lola», інший рід лишається, `stripGenus`; разом з «Інші назви» — і в доданих);
  назви батьків → точно як у магазині (описки, лапки, `nameFixes.ts`); «Походження з інших записів» (`planLineage`): з картки, блоку «Походження …» у формах (base),
  старих батьків невиправленої форми й перевірки — порожнє дописати, різне — «Було → Стане» з вибором варіанта (за замовчуванням — як у картці); форма (і «… hybrid» для своєї звичайної версії) з порожнім base отримує батьків звичайної версії;
  поле «Культивар» і подвійні лапки (`cultivarFixes.ts`). Правила порядку даних (`dataRules.ts`): рід у назві = поле «Рід»; написання назви (`normalizeName`:
  пробіли, прямі лапки, ×, рід латиною, форма одним словом); форма в назві = галочка; інша назва = власна назва; спільна інша назва з іншою рослиною (підказка; одна родина — за `familyKey`, як «Інші форми цієї рослини»); сама собі батько / батьки одна одної; суперечності походження
  (природний вид з батьками чи селекціонером; «можливий дубль» і «гібрид без батьків / відбір без Від» прибрано на прохання власниці); ареал природного виду з інших карток/перевірки;
  ареал однаково (`HABITATS`, англійські → українською); селекціонер однаково (вибір написання); назва гібрида чи культивару в лапках («Echeveria 'Lola'», відбір виду — «agavoides 'Maria'»), природний вид (і форми виду) з малої (`caseName`, правила «Назва в лапках» / «Вид з малої»; формули «A x B» не чіпає); «Написання «Від»» (форма, «Від» — та сама назва з іншими лапками чи без них, рослини немає в магазині); «Немає походження» (ні типу, ні батьків; назва в лапках після роду — пропонує «Гібрид», інакше підказка); «Селекціонер форми» — і записаний трохи інакше («Altman Plants» / «… (Renee O'Connell)»), і у форми, чиєї звичайної версії немає в магазині; рід в адресі сторінки інший, ніж у рослини («crassula-…» в Echeveria) — нова адреса з назви, стара йде в `oldSlugs` (сторінка товару за старою адресою знаходить товар і переходить на нову; індекс isActive + oldSlugs); «Форма в адресі» — variegata/cristata/monstrose в адресі не ті, що в назві (`slugForm`, так само нова адреса й oldSlugs; зайва форма в адресі — підказка, що могли забути галочку); «Походження з назви» (`baseFromName`: форма, звичайної версії немає в магазині, блок «Походження …» порожній — «Від» «Echeveria agavoides 'Maria'» → відбір від Echeveria agavoides, «Echeveria chihuahuaensis» → природний вид, ареал з інших записів чи перевірки, інакше порожній; не пропонується, якщо є «Походження з інших записів»); «Лапки в інших назвах» — «'Debbie'» → «Debbie» (`unquoteAlias`, рід із лапками лишається); «У продажу» без фото чи ціни — підказка для всіх товарів (правила «Опис» і «на складі 0» прибрано на прохання власниці). Підказки (patch: null) без галочки, з «Відкрити картку». Нічого не міняється без галочки. Товари керуються й прямо в магазині: кнопки
  продавця на картках, «Вибрати» (масові дії, `BulkBar`), «Додати» в каталозі й пошуку.
- Кабінет покупця (`features/account`): `/account` — плитки, бонусний рахунок і лише 3 останні записи історії бонусів;
  уся історія — `/account/bonuses` (`BonusesPage.tsx`, по місяцях), `/account/orders`, `/account/favorites`.
- Картка «Походження» на сторінці товару: імена рослин ведуть на сторінку цієї рослини (`PlantChip`, товар за точною назвою — `useProductByName`),
  немає в магазині — пунктирна плашка без посилання, а продавцю — з плюсиком: нова картка з назвою й відомим походженням
  (`/admin/products/new?name=…&origin=…&p1=…&p2=…&habitat=…`, `prefillPlant` у `admin/productSchema.ts`). Для форми й відбору — «Від [рослина]», під ним стрілка-гачок униз з підписом «Батьки [рослини]» / «… — природний вид» / «… — відбір від»
  (підпис — поза фоном), а під підписом на світлому фоні — батьки (`FromRow`, однаково на телефоні й комп'ютері): вписане у формі товару в згорнутому блоці «Походження Echeveria Lola» (поле `base`), інакше — з картки звичайної версії.
- «Інші форми цієї рослини» (під товаром) і «Родоводи» → «Форми» групують за `familyKey` (lib/plantName): без форм, «hybrid» і культивару
  в лапках після назви — chihuahuaensis, її 'Ruby Blush' і variegata разом; Orion і Orion hybrid разом. Культивар у спільних лапках («'Suyon Frill Gold'», поле «Культивар» = Frill Gold) — у родині самої назви (`familyKey(name, cultivarName)`, `withoutMergedCultivar`); без поля «Культивар» лапки не розбираємо («'Margaret Martin'» — окрема рослина).
- Пов'язані рослини під товаром — `catalog/RelatedPlants.tsx`: інші форми, батьки, гібриди від неї (блок «Зі спільним батьком» прибрано на прохання власниці); для рідкісних родів (до 10 рослин на сайті) — ще й «Інші рослини роду».
- Блог: статті прямо в коді — `web/src/features/blog/articles.ts`.
- Назви рослин і теги-форми: `web/src/lib/plants.ts`, `web/src/lib/plantName.ts`.
  Повна назва = рід + вид/назва + культивар у лапках + форми з галочок, напр. «Echeveria Lola variegata», «Echeveria agavoides 'Maria'».
  Поле «Культивар» у формі (`selection`; у товарі — `cultivarName`, назва й так містить його в лапках; `splitCultivar`/`plantBase` у `admin/productSchema.ts`):
  вписаний культивар сам ставить «Відбір або мутація» від виду/назви («Echeveria agavoides»). Назва вже в лапках + культивар → одні лапки:
  «'Monroe'» + «Black» = «Echeveria 'Monroe Black'», від «Echeveria 'Monroe'» (`plantBase`; при відкритті форма знову розділяє за `cultivarName`). Старі назви з двома парами лапок
  зливає «Інструменти → Виправлення», правило «Лапки» (`rename` у `cultivarFixes.ts`: назва + «Від», якщо він ішов за назвою). Старі назви зі словом у лапках форма показує
  в «Вид або назва», поки культивар не перенесли: «Інструменти → Виправлення», правило «Поле «Культивар»» (`cultivarFixes.ts`) пише лише `cultivarName`,
  назву й батьків не чіпає. «Echeveria 'Lola'» без назви перед лапками — назва гібрида, не культивар. Галочка «Hybrid» (тег `hybridName`, не плутати зі старим
  тегом `hybrid` і з полем «Походження») дописує «hybrid» — для гібрида без власної назви: «Echeveria Orion hybrid». Галочка сама ставить походження «Гібрид» і першого
  батька «Echeveria Orion»; з одним батьком у «Походженні» — «Гібрид від Echeveria Orion» і нижче батьки Orion (а не «Orion × невідомий»). Галочка форми (variegata/cristata/monstrose) сама ставить «Відбір або мутація» від рід + сорт (`applyFormOrigin`),
  а колишнє походження з картки переносить у блок «Походження …» (`base`). Коли форма сама ставить «Від» (форма, культивар, Hybrid) і ця рослина є в магазині — її батьки / «відбір від» / ареал одразу йдуть у блок «Походження …» (`fillBaseFrom`; лише якщо блок порожній або заповнений так само автоматично від попередньої «Від»). У «Виправленнях» й імпорті «hybrid» — частина назви (`withoutStates`), не форма: «Orion hybrid variegata» — від «Orion hybrid». Живцям на екрані дописується «(живець)»
  (`withCuttingMark`), у базі назва без цього.

- Пошук (`lib/search.ts`) не шукає за адресою сторінки (slug) — у ній після перейменування лишається стара назва.
- Швидкі дії продавця на картці (`useSetStock` тощо в `admin/api.ts`) правлять товар у кеші, а не перечитують сайт.
- Доставка: Нова Пошта (відділення) або таксі по Львову — галочка в оформленні з’являється, коли місто — Львів (`isLviv` у
  `lib/shop.ts` і `functions/src/schema.ts`); тоді відділення не потрібне, а **адресу не питаємо** — власниця пише покупцю сама.
  У замовленні `delivery.taxi` (`address` — лише в кількох перших). Вибір таксі запам'ятовується (`succulents.lastDelivery`,
  `users/{uid}.delivery.taxi`). Покупцям не обіцяти дзвінків — власниця пише, а не телефонує.
- Відвідувачі за день — адмінка «Покупці», вкладка «Відвідування» (?tab=visits: Сьогодні / Вчора / За 7 днів і графік за 30 днів): кожен браузер раз на добу (київський час)
  додає +1 у `visits/{YYYY-MM-DD}` (`lib/visits.ts`, у rules — рівно +1, читає лише продавець). Продавця не рахуємо.
- Подвійне замовлення: сайт шле `requestId`, `createOrder` пам'ятає його в `orderRequests/{id}` і на повтор віддає те саме замовлення.

- **Мінімум дублів в інтерфейсі** (прохання власниці): якщо назву розділу вже видно на вибраній вкладці/плашці/пункті меню —
  видимого заголовка не робити (лише `<h1 className="sr-only">` для читалок): адмінка (Товари, Покупці, Аналітика, Інструменти, Замовлення, огляд),
  сторінка категорії в магазині. Кнопки «Назад» — лише на глибших сторінках (товар, стаття, форма товару, кабінет), не в розділах із меню.

## Ролі й видимість

- Продавець (адмін) — `useAuth((s) => s.role === 'seller')`. Список email-ів має збігатися в чотирьох місцях:
  `firestore.rules`, `storage.rules`, `web/.env.production` (`VITE_SELLER_EMAILS`), `functions/.env.succulents-shop-ua`.
- Товар з `isActive: false` прихований: покупці його не бачать (так і в Rules). Продавець бачить приховані **скрізь**
  (каталог, головна, пошук, сторінка товару) з позначкою «Приховано» — запити в `catalog/api.ts` мають параметр `withHidden`.
- **«Готова до продажу»** (`forSale`): `false` — покупці бачать «Немає в наявності» й не можуть замовити, продавець бачить
  справжній залишок. Не вказано = продається (старі товари). Нові товари — приховані й не на продаж.
- Чи продавати, вирішує **лише** «У продажу»: у продажу — покупцю доступний увесь залишок, не на продаж — 0 (правила «остання рослина
  лишається в колекції» більше немає, прибрано 09.11.2026). Усе, що бачить покупець, проходить через `forBuyer()` / `buyerStock()` у `catalog/api.ts`;
  сервер (`createOrder`) перевіряє те саме. Продавцю (`withHidden`) — справжні залишки.
- Для продавця в магазині: замість «У кошик» — «Кількість на складі − N +», ряд Редагувати / око / іконка «У продажу» (зафарбована — у продажу;
  при 0 на складі — сіра, не перемикає, з підказкою; око зафарбоване — товар показано) / Видалити, шпилька під сердечком, під нею ножиці «Живець» (`CuttingToggle`, тег cutting; у списку адмінки й на сторінці товару — в ряду кнопок), «скопіювати назву» перед назвою;
  на сторінці товару — ті самі кнопки іконками під назвою;
  у каталозі — кнопка «Як бачить покупець» (?view=buyer: сторінка точно як у покупця, картки покупця + шпилька);
  у шапці немає кошика й кабінету, є «Адмінка». Головна для покупця — лише те, що є в наявності.
- «Нові надходження» на головній продавець бачить як покупець (`ProductGrid asBuyer`), лише зі шпилькою. Лише позначені шпилькою
  на картці (`onHome`, `useToggleOnHome`), у порядку, як позначали (`onHomeAt`), без обмеження кількості;
  інших рослин там немає. Позначені без наявності не показуються; нічого не позначено — покупцю блок не видно.
- Вітальні 100 грн — `functions/src/syncAccount.ts`, лише для підтвердженої пошти (Google — завжди). Продавець бонусів не бачить.

## Імпорт з таблиці (Google Sheet «Рослини»)

`/admin/import`: вставити рядки таблиці (TSV) → попередній перегляд → «Застосувати».
Логіка в `web/src/features/admin/sheetImport.ts`: перейменовує існуючі товари за правилами назв, нові рослини створює
**прихованими** (`isActive: false`, `forSale: false`, залишок 0, ціна = «Max ₴»). Фото й наявність не чіпає.
Кожна зміна (нова назва, нова рослина, оновлення даних) — з галочкою й «Було / Стане»; записується лише вибране.

## Локальна розробка

Емулятори Firebase (проєкт `demo-succulents`), справжній Firebase не потрібен:
```
npm run emulators   # термінал 1
npm run seed        # тестові товари й тестовий продавець (логін — у functions/scripts/seed.mjs)
npm run dev         # http://localhost:5173
```
У Claude desktop: dev-сервер «web» з `.claude/launch.json` (порт 5173). Firebase CLI на Windows — `npx.cmd firebase-tools`.
Перевірка перед публікацією: `npm --prefix web run lint` і `npm --prefix web run build`.

Підводні камені:
- Емулятор функцій на Windows інколи не встигає завантажити їх за 10 с — запускати з `FUNCTIONS_DISCOVERY_TIMEOUT=60`.
- Після кількох правок поспіль dev-сервер інколи тримає стару копію модуля («X is not defined», хоч build проходить) —
  перезапустити «web» (preview_stop / preview_start), а не шукати помилку в коді.
- Скріншоти панелі браузера інколи «з'їжджають» — допомагає resize_window preset desktop.
- Свої тестові дані — лише в емуляторі (`demo-succulents`); скрипт з firebase-admin через `createRequire` із `functions/`.

## Публікація

Push у `main` → GitHub Actions (`.github/workflows/deploy.yml`): lint → build → `firebase deploy` (сайт, функції, правила).
Займає кілька хвилин; стан — `https://api.github.com/repos/Khutor1234/succulents/actions/runs?per_page=1`
(без входу — не більше 60 запитів на годину, тож опитувати раз на 30 с; `gh` на цьому комп'ютері немає).
Коміти — українською, коротко описують зміну для людини.

Після публікації перевіряти: сайт відповідає 200, у бандлі є новий код, функції відповідають як слід
(`curl -X POST .../europe-central2-succulents-shop-ua.cloudfunctions.net/createOrder` → 400, `syncAccount` → 401; **500 — функції лежать**).
Firebase пропускає функції, «які не змінились» (навіть після невдалої спроби) — щоб примусово оновити, потрібна реальна зміна в `functions/src`.

Журнали функцій на проді (лише читання, з дозволу власниці): `npx.cmd firebase-tools functions:log --project succulents-shop-ua -n 100 --debug`
— без `--debug` часто падає «Failed to retrieve log entries»; повторювати кілька разів. 22–24.10.2026 функції не запускались
через збій на боці Google («instance could not start»), минулося саме.
