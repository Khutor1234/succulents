# Логи й помилки

Два інструменти, які доповнюють один одного:

| | Що показує | Де дивитись | Ціна |
|---|---|---|---|
| **Cloud Logging** | Усе, що робив сервер: кожне замовлення, вхід, зміна статусу, нарахування бонусів | Google Cloud Console → Logs Explorer | безкоштовно (50 ГБ/міс) |
| **Sentry** | Помилки на сайті й на сервері — зі стеком і тим, що людина робила перед помилкою | sentry.io | безкоштовно до 5 000 помилок/міс |

Особистих даних (email, телефон, адреса) немає ні там, ні там — лише **uid** покупця й **номери замовлень**.
Знайти uid за email: адмінка → «Покупці» або Firebase Console → Authentication.

## Що записується

**Сервер (усі функції):**
- `createOrder called` / `ok` / `rejected` / `failed` — хто (uid), скільки товарів, сума, бонуси, тривалість;
- `Order created`, `Order adjusted` — orderId, номер, що змінив продавець;
- `onOrderStatusChanged` — зміна статусу й що зробив тригер (нарахував/зняв бонуси, повернув товари);
- `syncAccount` — вхід, роль, вітальний бонус;
- `onOrderCreated` — Telegram-сповіщення.

«rejected» (WARNING) — нормальна відмова: немає на складі, неправильний телефон тощо.
«failed» (ERROR) — справжня помилка, вона ж іде в Sentry.

**Сайт (Sentry):**
- будь-яке падіння сторінки (замість білого екрана людина бачить «Ой, щось пішло не так»);
- невдале оформлення замовлення — з кошиком і кодом помилки;
- помилки входу (крім неправильного пароля — це не баг);
- будь-яка помилка читання чи збереження даних (каталог, адмінка, кабінет);
- «хлібні крихти» перед помилкою: додав у кошик → прибрав → натиснув «Оформити»…

## Як шукати в Cloud Logging

Google Cloud Console → вибрати проєкт → **Logs Explorer**. Приклади запитів:

```
jsonPayload.uid="<uid покупця>"
```
Усе, що робив конкретний покупець.

```
jsonPayload.number="SC-1042"
```
Уся історія замовлення: створення, зміни складу, статуси, бонуси.

```
severity>=WARNING
```
Лише відмови й помилки.

```
jsonPayload.fn="createOrder" AND severity=ERROR
```
Замовлення, які не вдалося створити через помилку.

## Підключити Sentry (≈10 хв, робиш ти)

1. Зареєструватися на https://sentry.io (можна через Google).
2. Створити **два проєкти**: платформа **React** (сайт) і **Node.js** (функції).
3. Скопіювати **DSN** кожного (Settings → Client Keys). Це публічні ключі для надсилання помилок, не секрет.
4. Надіслати їх Claude або вписати самій:
   - сайт — `web/.env.production`: `VITE_SENTRY_DSN=https://…`
   - функції — `functions/.env`: `SENTRY_DSN=https://…`
5. `firebase deploy`.

Локально (емулятори) Sentry вимкнений — помилки й «крихти» видно в консолі браузера (F12 → Console).

Зручно: у Sentry → Alerts увімкнути лист / Telegram-повідомлення при новій помилці.
